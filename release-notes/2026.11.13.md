# Task picker global filters, dotfile main_checkout, and faster shell prompts

`mise run` can now hide or show only global tasks in its picker, dotfile symlinks can point at a repository's main checkout so they survive worktree removal, and declared daemon URLs are exported as `<NAME>_URL`. `mise hook-env` and `mise env` also run faster in projects with many tools. This release fixes `mise set` on configs that use `[[env]]`, locked task tool pins, lockfile churn from `mise lock --bump`, and several packslip, task and Windows issues.

## Added

- **`mise run --no-global` / `--global`** filter the interactive task picker so it hides global tasks (from `~/.config/mise/config.toml` and `~/.config/mise/tasks`) or shows only those. Either flag opens the picker even when a `default` task exists, and both work with `--all` and `--multi`. [#15972](https://github.com/jdx/mise/pull/15972) (@jdx, @Guria)
- **`main_checkout` for dotfile symlinks.** Set `main_checkout = true` on a `symlink` or `symlink-each` entry and mise links to the same path in the repository's main checkout, so the link keeps working after `git worktree remove`. The source must exist in the main checkout. A worktree of a bare repository has no main checkout, so mise warns and links the source as written. [#16016](https://github.com/jdx/mise/pull/16016) (@jdx)

  ```toml
  [dotfiles]
  "~/.config/mise/config.toml" = { source = "mise.global.toml", main_checkout = true }
  ```

- **Daemon `url` exported as `<NAME>_URL`.** When the proxy doesn't serve a daemon (`proxy = false`, no `port`, or a hostname collision), mise renders the daemon's declared `url` template and exports it as `<NAME>_URL`. `[env]` can then refer to it, for example `BACKEND_ENDPOINT = "{{ env.API_URL }}"` for a daemon named `api`. Daemons the proxy serves still export their proxy hostname URL. The `url` template can use `{{ port }}`, `{{ ports }}` and `{{ name }}`. This needs pitchfork 2.36.0 or later. [#16040](https://github.com/jdx/mise/pull/16040) (@jdx, @jholzinger-hadrian)
- **Warnings for tool options that have no effect.** Core tools (node, python, go and the rest) and `dotnet:` used to accept any option silently. They now print a warning at install time for an option they don't read, and suggest the closest valid one (for example `lazy_bin` → `lazy_bins`). The install still succeeds. Backends that already rejected unknown options now include a "did you mean" hint in the error. `aqua:`, `asdf:` and `vfox:` tools are not checked. [#15986](https://github.com/jdx/mise/pull/15986) (@jdx)
- **`packslip.compinit` setting** (`MISE_PACKSLIP_COMPINIT`, default `true`). If your zsh plugin manager defers `compinit` (zinit, for example), set it to `false`. mise then skips its own `compinit -i` during activation and registers packslip completions once `compdef` exists. This avoids running `compinit` twice and writing the default `~/.zcompdump`. [#15996](https://github.com/jdx/mise/pull/15996) (@jdx, @drewbitt)
- **`prune.forget_unused_after` setting** (default `90d`). mise forgets tracked configs that haven't been loaded for this long, so old scratch projects stop keeping tool versions alive. Set it to `"0s"` to keep entries until the file is deleted. A tracked file that no longer exists stops protecting its versions right away, and its entry is forgotten after a week. [#15994](https://github.com/jdx/mise/pull/15994) (@jdx)
- **vfox plugin Lua APIs:** a new `checksum` module (`checksum.digest(path, "sha512")`, `checksum.verify(path, "sha256:<hex>")`, which supports sha256, sha512, sha1 and md5), plus `file.mkdir` and `file.remove` (directories need `{ recursive = true }`). Plugins no longer need to shell out to `sha256sum`, `mkdir -p` or `rm -rf`. [#16031](https://github.com/jdx/mise/pull/16031) (@jdx, @hexadecimal233)
- New registry tool: `reylo`. [#15992](https://github.com/jdx/mise/pull/15992) (@jdx, @colinhacks)

## Fixed

### Config and environment

- `mise set` and `mise unset` no longer panic on a `mise.toml` that uses `[[env]]` groups or inline `env = { ... }`. Edits follow the order mise applies the groups in:
  - `set` rewrites the entry that takes effect, including a `tools = true` entry, which keeps `tools = true`.
  - `unset` removes the key from every group.
  - `mise set KEY` prints the value mise actually exports.

  Dotted keys are handled consistently. An edit that would leave an `env` table mise can't load is rejected and the file is left as it was. [#15987](https://github.com/jdx/mise/pull/15987), [#16000](https://github.com/jdx/mise/pull/16000) (@jdx)
- Ceiling paths (`MISE_CEILING_PATHS` or `ceiling_paths` in `.miserc.toml`) that go through a symlink now stop the config search, matching Git's `GIT_CEILING_DIRECTORIES`. On Windows, ceilings also work when the start directory has a `\\?\` prefix. [#15997](https://github.com/jdx/mise/pull/15997), [#16010](https://github.com/jdx/mise/pull/16010) (@jdx)
- When `.tool-versions` is the global config file, mise no longer prints a TOML parse error from the settings loader on every command. [#15980](https://github.com/jdx/mise/pull/15980) (@jdx)
- When a command wrapper runs its own command again and nothing provides that command, the error now names the wrapper, the file that declares it and its command, and explains whether `disable_tools`/`enable_tools` or a missing install is the cause. It used to say "is not a valid shim". [#16021](https://github.com/jdx/mise/pull/16021) (@jdx, @CR1MS0N-Operator)
- Experimental labels in `schema/mise.json` now match what mise enforces. `[bootstrap.users]` and `[bootstrap.groups]` are no longer marked experimental, and `spinel:` tools now are. [#15983](https://github.com/jdx/mise/pull/15983) (@jdx)

### Tasks

- With `--locked`/`MISE_LOCKED=1`, a task's `tools` pin is now read from the task config's own `mise.lock` when a parent config lists the same tool at another version. Before, the task could run without the pinned tool on `PATH`. [#15969](https://github.com/jdx/mise/pull/15969) (@jdx)
- A `mise run` started in the background by a script no longer sometimes hangs forever after receiving SIGINT. [#15991](https://github.com/jdx/mise/pull/15991) (@jdx)
- Task output in the silent style (`--silent`, `--output silent`, `MISE_TASK_OUTPUT=silent`, `output = "silent"`) is no longer exported as OpenTelemetry logs. [#15975](https://github.com/jdx/mise/pull/15975) (@jdx)
- The remote task cache client now follows a server's `307` redirect for blob downloads. It sends no cache credentials to the delegated host, requires HTTPS and still verifies the digest. It also honors `Retry-After` on 429/503, waiting up to 30 seconds in total. A redirected upload is now reported as a failure instead of counting as success. [#15981](https://github.com/jdx/mise/pull/15981) (@jdx)

### Lockfiles

- With `minimum_release_age` set, `mise lock --bump` no longer rewrites a `pipx:`/`pypi:` tool's `uv.lock` and its digest in `mise.lock` when only the `exclude-newer` cutoff changed. Scheduled update bots stop opening lockfile-only PRs. [#16036](https://github.com/jdx/mise/pull/16036) (@jdx, @tecnobrat)
- A packslip signer now replaces leftover `cosign` or `minisign` provenance from an older `mise backends switch`. `mise upgrade`, `mise lock --bump` and auto-updates no longer fail with "would downgrade recorded provenance". [#15995](https://github.com/jdx/mise/pull/15995) (@jdx)
- `mise install` and `mise lock` no longer suggest `mise backends switch` for a yarn, bun, npm or pnpm backend that a `packageManager` checksum forces. [#16032](https://github.com/jdx/mise/pull/16032) (@jdx)

### Upgrade and prune

- `mise upgrade` scans tracked configs much faster. In one test with 1,422 tracked configs, the scan took about 6s instead of 15.7s. Problems in other projects are summarized in one warning that points to `mise prune --dry-run`. The scan now uses installed versions offline, so a project's installed `node = "20"` version stays protected. [#15994](https://github.com/jdx/mise/pull/15994) (@jdx)

### Packslip and shells

- Installing a packslip tool that declares a skill no longer fails when your GitHub token is expired or revoked. A 404 from raw.githubusercontent.com is retried once without the token, and mise warns about the token. [#16022](https://github.com/jdx/mise/pull/16022) (@jdx, @scop)
- Packslip `requires.libs` checks no longer report "cannot check shared library" on desktop Linux systems with large loader caches. Debian/Ubuntu multiarch directories are now searched directly. [#16022](https://github.com/jdx/mise/pull/16022) (@jdx, @scop)
- Zsh completion cleanup no longer prints `unfunction` errors in shells restored from a snapshot, such as Claude Code's. [#15993](https://github.com/jdx/mise/pull/15993) (@jdx)

### Backends and system packages

- vfox plugin commands always run with `sh -c` / `cmd /C` again, regardless of `unix_default_inline_shell_args`/`windows_default_inline_shell_args`. This fixes Windows plugin installs that broke with `windows_default_inline_shell_args = "sh -c"`. Those settings still apply to tasks and other inline commands. [#16037](https://github.com/jdx/mise/pull/16037) (@jdx)
- On Windows, `mise sync python --uv` now finds uv's pythons in `%APPDATA%\uv\python`. Copies into uv's directory now use uv's `cpython-{v}-{os}-{arch}-{libc}` naming on every platform. [#16007](https://github.com/jdx/mise/pull/16007) (@jdx, @lurkerlin)
- `mise bootstrap packages` now warns about unsupported custom Homebrew `Requirement` classes only when it is about to pour or build the formula, not on runs where nothing needs installing. [#15973](https://github.com/jdx/mise/pull/15973) (@jdx, @skoch13)
- `mise dot apply` of a `mode = "copy"` directory with thousands of files takes seconds instead of minutes. For example, 3,000 files dropped from about 137s to under 1s. [#16039](https://github.com/jdx/mise/pull/16039) (@jdx, @webkaz)

## Changed

- **Performance:** a series of changes reduces the work done on every command. The changes are:
  - caching the parsed `mise.lock` between commands
  - reading lockfile entries once
  - checking each tool's installation once per command
  - building settings once at startup
  - not resolving backtraces for errors mise discards

  In a project with 29 tools, `mise hook-env` and `mise env` are several percent faster per change. Checking installs once per command alone cuts `mise hook-env` from about 15.3 ms to 14.1 ms. [#15999](https://github.com/jdx/mise/pull/15999), [#16001](https://github.com/jdx/mise/pull/16001), [#16002](https://github.com/jdx/mise/pull/16002), [#16003](https://github.com/jdx/mise/pull/16003), [#16004](https://github.com/jdx/mise/pull/16004), [#16023](https://github.com/jdx/mise/pull/16023), [#16024](https://github.com/jdx/mise/pull/16024), [#16025](https://github.com/jdx/mise/pull/16025), [#16026](https://github.com/jdx/mise/pull/16026), [#16034](https://github.com/jdx/mise/pull/16034), [#16035](https://github.com/jdx/mise/pull/16035), [#16041](https://github.com/jdx/mise/pull/16041) (@jdx)
- The bundled `url` crate is updated to 2.5.9 to address RUSTSEC-2026-0592. [#16015](https://github.com/jdx/mise/pull/16015) (@jdx)

## Deprecated

- **`MISE_USE_TOML=0`** is deprecated and will be removed in mise 2027.11.0. It still works, and mise keeps reading `.tool-versions` files. mise warns once per run when the variable changes what a command does, but not from shims or `hook-env`. [#15980](https://github.com/jdx/mise/pull/15980) (@jdx)

  To migrate:
  - To write a `.tool-versions` file, use `mise use --path .tool-versions`.
  - To keep `~/.tool-versions` as the global config, set `MISE_GLOBAL_CONFIG_FILE=~/.tool-versions`.
