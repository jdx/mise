# MacPorts support in bootstrap, self-update before tool updates, and `published_at` release ordering

`mise bootstrap` can now manage MacPorts ports and update mise itself before tools. GitHub, GitLab and Forgejo tools can follow the most recently published release, and Homebrew tap formulae can pour bottles and download from private GitHub releases. This release also fixes `http:` checksum verification, shims for `path:` versions, `mise unuse -g` with split global configs, Windows Server Core startup, and several task, bootstrap and Java issues.

## Added

### Bootstrap

- **MacPorts package manager.** On macOS, you can declare ports in `[bootstrap.packages]` with the `macports:` prefix and install or remove them with `mise bootstrap`. mise finds `port` on `PATH` or at `/opt/local/bin/port`, and runs installs, upgrades and removals through the existing sudo handling. It never runs `port selfupdate` and does not install MacPorts itself. Version pins are checked against the active port but can't be installed. Unprefixed keys don't use MacPorts unless you add it to `system_packages.prefer`. [#15862](https://github.com/jdx/mise/pull/15862) (@jdx, @snuxoll)

  ```toml
  [bootstrap.packages]
  "macports:ripgrep" = "latest"
  "macports:bc" = { state = "absent" }
  ```

- **Update mise before tools.** Both options are opt-in and the defaults are unchanged. [#15897](https://github.com/jdx/mise/pull/15897) (@jdx)
  - `mise bootstrap --self-update` updates mise, then runs the same bootstrap again with the new binary. If the update fails, nothing is applied. The flag is ignored with `--dry-run` and for subcommands.
  - `tool_update.self_update_first = true` makes each automatic tool update pass check for and install a newer mise first. This requires `self_update.auto`. If the mise update fails, tools are skipped until the next interval and `mise doctor` shows the error. It is skipped in CI, in offline modes and for mise installed by a package manager.

  ```toml
  [settings]
  self_update.auto = true
  tool_update.self_update_first = true
  ```

### Homebrew taps (system packages)

- Formulae from third-party taps now pour the bottles the tap declares in its `bottle do` block instead of always building from source. Only a bottle for the exact host tag or `all` is used. Formulae with `post_install` or `pour_bottle?` restrictions still build from source. [#15893](https://github.com/jdx/mise/pull/15893) (@jdx)
- Tap formulae that use a custom download strategy to fetch GitHub release assets, usually from a private repo, can now be installed. mise doesn't run the Ruby strategy. It downloads the asset through the GitHub API with your configured GitHub credentials (`MISE_GITHUB_TOKEN`, `github.credential_command`, and so on) and checks its sha256. This works for both source builds and bottles. Other custom strategies are still rejected. [#15898](https://github.com/jdx/mise/pull/15898) (@jdx)
- Source builds now support `virtualenv_install_with_resources` from Homebrew's `Language::Python::Virtualenv`. mise verifies each resource against its sha256 and installs it into a venv in the keg's `libexec`, then links the formula's console scripts into `bin`. [#15896](https://github.com/jdx/mise/pull/15896) (@jdx)

### Tools

- **`version_order = "published_at"`** makes `latest` follow the release that was published most recently, even when its version number is lower. This is useful for repos that ship both stable and prerelease builds, where GitHub doesn't always list releases in publication order. `mise latest`, `mise upgrade` and `auto_update` all use this order. It works with github, gitlab and forgejo tools. [#15860](https://github.com/jdx/mise/pull/15860) (@jdx)

  ```toml
  [tools]
  "github:openai/codex" = { version = "latest", prerelease = true, version_prefix = "rust-v", version_order = "published_at" }
  ```

- **`exclude-newer = false` on a PyPI index.** It turns off the `minimum_release_age` cutoff for packages from that index only. Use it for indexes that don't serve upload times, such as GitLab's PEP 503 index. Previously, uv filtered out every release from those indexes. `false` is the only accepted value. [#15885](https://github.com/jdx/mise/pull/15885) (@jdx)

  ```toml
  indexes = [{ name = "private", url = "<index-url>", explicit = true, exclude-newer = false }]
  ```

- New registry shorthand `rtk-proxy` for the proxy daemon that ships in `rtk-ai/rtk` releases. Note that the proxy is licensed separately (BUSL-1.1). [#15915](https://github.com/jdx/mise/pull/15915) (@jdx)

### Tasks

- **`if_pool` on task locks.** With `if_pool = true`, a task takes the lock only on machines whose `task.lock_pools` declares that name. On other machines it runs without the lock. It also works with `count`. [#15917](https://github.com/jdx/mise/pull/15917) (@jdx)

  ```toml
  [tasks.benchmarks]
  lock = { name = "xcode", if_pool = true }
  ```

### Dotfiles and GitHub tokens

- **`history.allow_secret_values`.** This global-only setting (also `MISE_HISTORY_ALLOW_SECRET_VALUES`) lists specific values that the dotfile history secret scan ignores, such as `"ctx7_api_key"`. A listed placeholder no longer blocks history sync. The same key with another value, or a real token on the same line, is still refused, and the rest of the scan stays on. [#15864](https://github.com/jdx/mise/pull/15864) (@jdx)
- When `gh` keeps its token in the system keyring, `mise token github` now prints a hint on stderr that suggests a `credential_command` using `gh auth token`. Stdout and `--raw` output are unchanged. [#15868](https://github.com/jdx/mise/pull/15868) (@jdx, @FalkWoldmann)

## Fixed

### Installs and tools

- `http:` tools with `checksum_url` now verify the download against the published checksum when installing, and record that checksum in `mise.lock`. Previously the checksum was used only by `mise lock`, so a wrong download could install without an error. A mismatch or an unresolvable checksum now fails the install. An explicit `checksum` or lockfile entry still takes precedence. [#15908](https://github.com/jdx/mise/pull/15908) (@jdx)
- `mise reshim` now creates shims for tools whose version is `path:...`. Previously a shim-based shell reported `command not found` even though `mise which` found the tool. [#15866](https://github.com/jdx/mise/pull/15866) (@jdx)
- Archives that contain absolute symlinks to files inside the same archive (for example osquery's `/opt/...` links) install again. mise rewrites those links as relative links. Links to paths outside the archive are still refused. [#15857](https://github.com/jdx/mise/pull/15857) (@jdx, @bendrucker)
- A non-root `mise install` no longer fails with `failed to rebuild runtime symlinks` when a tool is installed only in another user's read-only shared or system installs directory. [#15858](https://github.com/jdx/mise/pull/15858) (@jdx)
- `gem:` tools keep working after a Ruby patch upgrade when one of their dependencies was installed only in the old Ruby's gem directory. mise now copies those dependencies into the tool's own install. [#15907](https://github.com/jdx/mise/pull/15907) (@jdx)
- `mise upgrade` now detects new commits for npm git sources that track HEAD, so `--prune` removes the old commit. Previously, commit SHAs were compared as version strings. [#15905](https://github.com/jdx/mise/pull/15905) (@jdx)
- `.sdkmanrc` Temurin versions with a fourth segment now install. Hotfix versions such as `26.0.2.1+1-tem` and regular releases such as `21.0.13.0+9-tem` now map to the matching catalog builds. [#15877](https://github.com/jdx/mise/pull/15877), [#15906](https://github.com/jdx/mise/pull/15906) (@jdx)
- `mise oci push` now rewrites both lines of uv's long-path launcher in `pypi:` tool layers. Previously, images built in CI could fail with `.../.mise-uv/.venv/bin/python: not found`. Layers cached from earlier pushes are not reused. [#15879](https://github.com/jdx/mise/pull/15879) (@jdx)

### Windows

- `mise.exe` and `mise-shim.exe` now link the C runtime statically, so they start on Windows Server Core images without the VC++ redistributable. Previously they exited silently with `0xC0000135`. [#15852](https://github.com/jdx/mise/pull/15852) (@jdx)
- `mise activate bash` in Git Bash now produces valid `PATH` entries when mise was installed with Scoop and runs through the Scoop shim. [#15863](https://github.com/jdx/mise/pull/15863) (@jdx)

### Config and CLI

- `mise unuse -g` now removes a tool from every global config file that declares it, including files written through `settings.write_targets.tools`. Previously it edited only `config.toml` and did nothing for tools declared elsewhere. `unuse` also warns when none of the given tools are declared, instead of exiting silently. [#15884](https://github.com/jdx/mise/pull/15884) (@jdx, @theblop)
- `enable_tools` and `disable_tools` (and `MISE_ENABLE_TOOLS`/`MISE_DISABLE_TOOLS`) now accept the same legacy names as `[tools]`, such as `nodejs`, `golang`, `dotnet-core` and `core:` prefixes. [#15880](https://github.com/jdx/mise/pull/15880) (@jdx, @mfroembgen)
- Commands such as `mise install` no longer warn about ignored global-only settings in tracked configs from other folders, because those settings never apply to the current folder. The warning still appears inside the folder that owns the config. [#15919](https://github.com/jdx/mise/pull/15919) (@jdx, @owpac)
- Tera deprecation warnings now name the config file that uses the deprecated helper. [#15927](https://github.com/jdx/mise/pull/15927) (@jdx, @Thomascountz)
- `mise doctor` no longer crashes when an asdf or vfox plugin repo has no commits. It shows the plugin as `(unknown)`, and plugin install or update now reports an error in this case instead of panicking. [#15850](https://github.com/jdx/mise/pull/15850) (@jdx, @xanathar)

### Tasks and deps

- A bare `depends` name in a monorepo task now falls back to a global task when the project has no task with that name. `depends = ["::name"]` now gives a clearer error. [#15851](https://github.com/jdx/mise/pull/15851) (@jdx)
- Tasks with `cache.command_inputs` no longer fail with `command output pipes did not close within 10s` on heavily loaded machines. [#15916](https://github.com/jdx/mise/pull/15916) (@jdx, @brodienguyen)
- With `rust` configured, `mise run` now checks each toolchain's rustup state once per run instead of twice. [#15878](https://github.com/jdx/mise/pull/15878) (@jdx)
- `mise deps` now marks the `uv` provider stale when a workspace member's `pyproject.toml` changes. It also marks the `pnpm` provider stale when `pnpm-workspace.yaml` or a member's `package.json` changes. An explicit `sources` list still replaces the defaults. [#15918](https://github.com/jdx/mise/pull/15918), [#15926](https://github.com/jdx/mise/pull/15926) (@jdx)

### Bootstrap and system packages

- `mise bootstrap` now runs a monorepo root's `bootstrap` task (`//:bootstrap`). Previously it was skipped. [#15853](https://github.com/jdx/mise/pull/15853) (@jdx)
- If no remote environment is set with `mise_env` or `--remote-env`, `mise bootstrap remote` now lets the host's miserc choose its config environments. Previously it forced an empty `MISE_ENV`. An explicit `mise_env = []` still selects none. [#15865](https://github.com/jdx/mise/pull/15865) (@jdx, @Guria)
- `mise bootstrap --dry-run` now previews dotfiles declared by a conf.d config that a `mode = "template"` dotfile renders. The preview only renders templates that don't need commands, environment variables, file reads or secrets. [#15861](https://github.com/jdx/mise/pull/15861) (@jdx)
- A cask that can't be resolved, such as one from a tap that returns 404, is now reported as `error` on its own line. Other packages are still checked and applied, and the command exits non-zero at the end. Previously the whole status check or bootstrap stopped. [#15909](https://github.com/jdx/mise/pull/15909) (@jdx)
- `mise bootstrap packages prune` now keeps the runtime dependencies (including indirect ones) of the formulae you declared, so it no longer removes libraries they link against. [#15890](https://github.com/jdx/mise/pull/15890) (@jdx)
- Casks from third-party taps that use `command_wrapper` now install. Previously they failed with an unsupported DSL error, which also broke the cask check in `mise doctor`. [#15891](https://github.com/jdx/mise/pull/15891) (@jdx)
- mise can now infer the version of a tap formula whose archive name has no dots, such as `LUFA-210130.tar.gz` or a date. [#15892](https://github.com/jdx/mise/pull/15892) (@jdx)
- When a `[dotfiles]` merge key has no `/<id>` segment, the error now says so and suggests the corrected key. [#15859](https://github.com/jdx/mise/pull/15859) (@jdx)
