# Experimental cache.sandbox for cached tasks

Cached tasks can now run in an experimental Linux sandbox. The sandbox blocks reads and writes that the task's cache declaration doesn't cover, so the task fails instead of storing a wrong result. `mise hook-env`, `mise env` and `mise ls` also run faster in projects with many tools.

## Added

- **`cache.sandbox` for cached tasks (experimental, enforced on Linux only).** A cached task is only correct if everything that affects its result is part of the cache key. With `cache.sandbox = true`, mise uses Landlock to restrict the task to its cache declaration. A read or write outside that declaration now makes the task fail instead of producing a cache entry that mise could restore for inputs it never checked. `cache.audit` only reports these reads after the run. [#16043](https://github.com/jdx/mise/pull/16043) (@jdx)

  ```toml
  [settings]
  experimental = true

  [tasks.build]
  run = "cat src/app.txt notes.txt > dist/out.txt"
  sources = ["src/**"]
  outputs = ["dist"]
  cache = { enabled = true, sandbox = true }
  ```

  In this example `notes.txt` is not listed in `sources`, so the task fails with `Permission denied`.

  - **Reads:** files matched by `sources`, the config files that define the task, outputs of its cached `depends` tasks, system paths and mise-installed tools. File names in the task directory can be listed, but other files' contents cannot be read.
  - **Writes:** only the directories that hold `outputs`, plus a private `TMPDIR` that all of the task's `run` entries share. The shared `/tmp` is blocked.
  - **Environment and network:** environment variables are limited to the essential ones, the task's own `env`, `cache.env`, `task_config.global_env` and `pass_through_env`. Network access is blocked.
  - **Extra paths:** add them with `allow_read` and `allow_write`. The paths become part of the cache key, but file contents do not, so a file that changes the result belongs in `sources`. Tools mise didn't install, such as a toolchain in `~/.cargo`, need an `allow_read` entry.
  - **Outputs:** outputs can't share a directory with sources. For example, `sources = ["*.c"]` with `outputs = ["*.o"]` is an error before the task starts. mise creates output directories before the run and removes any the task leaves empty.
  - **Configuration:** `task_config.cache` accepts the key, so you can turn it on for every eligible task. `--task-cache off` does not turn the sandbox off. `mise tasks ls --json` and `mise tasks info --json` show a `sandbox` field inside `cache`.
  - **Cache entries:** entries made in the sandbox are keyed separately, so mise never restores an entry stored without the sandbox for a task that asks for it.
  - **Other platforms:** on macOS and Windows, mise warns once and runs the task without the sandbox.

## Changed

- In file tasks, an invalid `#MISE cache=...` header is now an error. Previously mise warned and dropped the whole `cache` value. A `#MISE` header line with a key and no value, such as `#MISE deny_net=`, is also now an error. Previously mise skipped it silently, so the task ran without that restriction. [#16043](https://github.com/jdx/mise/pull/16043) (@jdx)

## Performance

- Every command does less redundant work. mise makes fewer filesystem checks, does much less memory copying, reads environment variables far less often and parses lockfile entries more cheaply. In a 29-tool project, `mise hook-env` makes about 13% fewer system calls. The environment-variable lookups per command drop from about 2,800 to about 500, which matters most in shells that export many variables. Behavior does not change. [#16044](https://github.com/jdx/mise/pull/16044), [#16050](https://github.com/jdx/mise/pull/16050), [#16051](https://github.com/jdx/mise/pull/16051), [#16052](https://github.com/jdx/mise/pull/16052) (@jdx)
