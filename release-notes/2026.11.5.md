# `mise dot files` shows what is tracked in a directory

This release adds `mise dot files` to show which files in a directory are tracked, and a `status.show_env_ignore` setting to hide variables from the status line. It also lets dot commands accept relative paths, stops warning when you save dotfiles by hand, and fixes downloads that failed because `~/.netrc` held a stale login.

## Added

- **`mise dot files`.** Lists the files and subdirectories in a directory and shows the state of each one, so you no longer have to work out how `[dotfiles]` entries, their `exclude`/`include` lists and `[history] exclude` apply. The possible states are:
  - `tracked`: saved to history. The row shows the entry that covers it and whether it autosaves.
  - `excluded`: covered by an entry, but a rule leaves it out. The row names the rule.
  - `omitted`: selected, but capture skips it, for example a file that looks like a credential.
  - `untracked`: no entry covers it.
  - `partial`: a directory that isn't tracked itself but contains tracked files.
  - `local`: a path kept in local-only history (`mode = "track-local"`).

  `PATH` defaults to the current directory and can be a relative path or a single file. `-r`/`--recursive` lists every file below the directory, `--tracked` and `--untracked` filter the rows, and `--json` prints one object per row. The command uses the same exclusion check as `mise dot save`, so the two always agree. [#15456](https://github.com/jdx/mise/pull/15456) (@jdx, @farangkao)

  ```console
  $ mise dot files ~/.config
  untracked  cache/
  partial    foot/   1 file tracked below
  tracked    hypr/   1 file · ~/.config/hypr (track, autosave)
  untracked  mise/
  ```

- **`status.show_env_ignore`.** With `status.show_env` on, mise lists every variable it sets each time you enter a directory, including variables that never change. This new setting takes variable names or shell globs to leave out of that line. You can also set it with `MISE_STATUS_MESSAGE_SHOW_ENV_IGNORE` as a comma-separated list. Changes to config files and paths are still shown. mise warns about malformed patterns and ignores them. [#15454](https://github.com/jdx/mise/pull/15454) (@jdx)

  ```toml
  [settings.status]
  show_env = true
  show_env_ignore = ["GO*", "DENO_INSTALL_ROOT"]
  ```

  With this config, `mise +DENO_INSTALL_ROOT +GOBIN +GOROOT +LUA_INIT` becomes `mise +LUA_INIT`.

## Fixed

- **Relative paths in `mise dot` commands.** `mise dot track config.toml` used to fail with `target must be absolute or start with ~/`. `track`, `untrack`, `add` and `edit` now resolve relative paths from the current directory the way a shell does, including `..` after a symlinked directory. A path inside your home directory is saved in its `~/` form. Exclude and include rules are still relative globs. [#15455](https://github.com/jdx/mise/pull/15455) (@jdx, @farangkao)
- **No warning when saving dotfiles by hand.** If you haven't set up the `history-watch` service, `mise dot track` now prints an info message about saving with `mise dot save` instead of a warning, so `--quiet` hides it. `mise dot status` now lists automatic capture as `manual`, without a warning or a suggested next step. mise still warns if the watcher is set up but not running, or if captures fail. [#15455](https://github.com/jdx/mise/pull/15455) (@jdx, @farangkao)
- **401 errors caused by stale `~/.netrc` credentials.** Some downloads failed with `401 Unauthorized` even though the server would serve the file without logging in. For example, `mise install glab` failed against gitlab.com when `~/.netrc` held a login that gitlab.com no longer accepted. If the only credentials came from netrc and the server returns 401, mise now retries once without them. Later retries of the same download also leave them out. Requests that carry their own `Authorization` header (such as forge tokens) and requests redirected to another host are not retried this way. [#15451](https://github.com/jdx/mise/pull/15451) (@jdx)
