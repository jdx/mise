# Project-scoped uninstall, JSONC dotfile merges, and node@lts moves to Node.js 26

You can now uninstall only the tools the current project requests, and new `--no-global` and `--project` flags replace the two different meanings `--local` had. Dotfiles can merge into JSONC files like VS Code's `settings.json` and can seed a file once without overwriting later edits. `node@lts` now resolves to Node.js 26. The rest of the release adds an `ipv4_only` setting, JSON output for `mise vars`, and fixes for Windows, lockfiles, pruning and GitHub release listing.

## Added

- **`mise uninstall --project` and `mise ls --project`.** `mise uninstall --project` removes the installed versions requested by the nearest project's config files: `mise.toml`, `mise.local.toml`, `conf.d` fragments, `.tool-versions` and idiomatic version files in that directory. Config in parent directories and global config is not included. It lists each version with the file that requests it and asks before removing anything. `--yes` skips the prompt, and `--dry-run` only shows the list. `mise ls --project` lists the same scope. Installs are shared between projects, so another project using the same version will need to reinstall it. [#15079](https://github.com/jdx/mise/pull/15079), [#15081](https://github.com/jdx/mise/pull/15081) (@jdx, @httpete-broadcom)

  ```console
  $ cd ~/work/app            # ~/work/mise.toml also exists
  $ mise ls --no-global      # app's config and ~/work's, not the global config
  $ mise ls --project        # app's config only
  $ mise uninstall --project # removes the versions app's config names, after asking
  ```

- **`--no-global` on `ls`, `outdated`, `upgrade` and `tasks ls`.** It selects tools or tasks from all non-global config, including parent directories, and does what `--local` did on these commands. [#15081](https://github.com/jdx/mise/pull/15081) (@jdx)
- **Dotfile merges into JSONC files.** A `merge` entry can now edit files that contain comments and trailing commas, such as VS Code's `settings.json`. It keeps the file's comments, indentation and any keys the source doesn't set. `.jsonc` targets are detected automatically. For other files, set the new `format` key (`json`, `jsonc`, `toml` or `yaml`). A `.json` target without `format` is still parsed as strict JSON. Merge sources that fail to parse now report the file path and the parse error. [#15077](https://github.com/jdx/mise/pull/15077) (@jdx, @TimonLukas)

  ```toml
  [dotfiles]
  "~/.config/Code/User/settings.json/shared" = { source = "vscode/shared.json", merge = true, format = "jsonc" }
  ```

- **`create_if_missing` for dotfiles.** `copy`, `template` and inline `content` entries with `create_if_missing = true` write the target only when nothing exists there. After that, local edits are left alone and do not count as drift in `mise dot status` or `mise dot diff`. If you delete the target, the next apply creates it again. This works for files that are filled in on each machine, such as local tokens. [#15080](https://github.com/jdx/mise/pull/15080) (@jdx, @thernstig)

  ```toml
  [dotfiles]
  "~/.config/mise/conf.d/private.local.toml" = { source = "templates/private.toml", mode = "copy", permissions = "0600", create_if_missing = true }
  ```

- **`permissions` on dotfile `merge` entries.** The mode is applied only when the merge creates the file. Files that already exist keep their mode. Merge entries for the same file must not set different modes. [#15087](https://github.com/jdx/mise/pull/15087) (@jdx, @thernstig)
- **`ipv4_only` setting.** Set `ipv4_only = true` (or `MISE_IPV4_ONLY=1`) for networks where a host fails over IPv6, for example `dl.google.com` returning 404 or Sigstore TUF fetches failing. This applies to mise's own HTTP connections: downloads, version lookups, GitHub API calls, attestation verification and vfox plugins. External programs such as `git`, `npm` and the `npm:` backend's package manager still use the system resolver. The default is `false`. [#15057](https://github.com/jdx/mise/pull/15057) (@jdx, @Alby02)
- **`mise vars --json` and `--json-extended`.** Prints vars as JSON. `--json-extended` also includes the file each value comes from. Redacted values stay `[redacted]`. [#15069](https://github.com/jdx/mise/pull/15069) (@jdx, @artemklevtsov)
- **`mise shell --unset --all`.** Removes every `MISE_<TOOL>_VERSION` override from the current shell in one command, including ones you exported by hand. [#15088](https://github.com/jdx/mise/pull/15088) (@jdx, @wfouche)
- **Bootstrap hook descriptions.** A hook table can set `description`, and `mise bootstrap` prints it instead of the hook's script. Without a description, mise prints `$` followed by the command's first line, cut to the terminal width. `--verbose` and `--dry-run` still print the full script. [#15106](https://github.com/jdx/mise/pull/15106) (@jdx, @owpac)

  ```toml
  [bootstrap.hooks.final]
  description = "Remove the root copy of pam_reattach if Homebrew removed the module"
  run = "..."
  ```

- Debian packages from the mise APT repository now include Bash, Zsh and Fish completions. [#15074](https://github.com/jdx/mise/pull/15074) (@gilesw)
- Registry: added an aqua backend for `oxfmt`. [#15092](https://github.com/jdx/mise/pull/15092) (@scop)

## Changed

- **`node@lts` now resolves to Node.js 26**, which entered Active LTS on 2026-10-28. It used to resolve to 24. `lts/lithium` (also `lts-lithium`) selects the 26.x line. Aliases for older lines, such as `lts/krypton`, are unchanged. To stay on Node.js 24, pin `node@24` or `node@lts/krypton`. [#15105](https://github.com/jdx/mise/pull/15105) (@jdx)
- Setting `system_packages.elevate_with = ""` now means "never elevate": package manager commands run as the current user. This helps on hosts without root, such as Termux. Before, an empty value fell back to `sudo`, `run0` or `doas`. If the setting is unset, mise still picks an elevator from `PATH`. [#15049](https://github.com/jdx/mise/pull/15049) (@jdx, @iliqiliev)

## Deprecated

- `--local` on `ls`, `outdated`, `upgrade` and `tasks ls` is deprecated in favor of `--no-global`. It still works and prints no warning for now. Warnings start in 2027.1.0, and the flag is removed in 2027.7.0. `settings --local` and `lock --local` are not affected. [#15081](https://github.com/jdx/mise/pull/15081) (@jdx)

## Fixed

- On Windows, background tool updates started from the shell prompt no longer open a visible console window for each tool. [#15038](https://github.com/jdx/mise/pull/15038) (@yusoofsh)
- `mise prune` and automatic upgrade pruning used to keep every version of a tool while a process started through a runtime link such as `installs/claude/latest` was running. They now keep only the version that process is running, so long-running sessions no longer stop old versions from being cleaned up. [#15113](https://github.com/jdx/mise/pull/15113) (@jdx)
- `mise install pipx:<tool>` no longer fails with `missing lockfile entry` when `lockfile_platforms` lists only the current platform. [#15091](https://github.com/jdx/mise/pull/15091) (@jdx, @drewbitt)
- When api.github.com times out (5xx) listing releases for repositories with many assets per release, such as `github:be5invis/Iosevka`, mise now retries with smaller pages of 30 and then 10 releases instead of failing. [#15078](https://github.com/jdx/mise/pull/15078) (@jdx)
- `mise version --json` no longer reports a `latest` older than the running version, which happened with fresh or nightly builds because of `minimum_release_age`. [#15068](https://github.com/jdx/mise/pull/15068) (@jdx)
- `mise backends switch` no longer fails with `No such file or directory` when the `locks/` directory next to it exists but is empty. Rollback after a failed switch also restores sidecar directories more reliably. [#15060](https://github.com/jdx/mise/pull/15060) (@zeitlinger)
- Packages from a custom aqua registry whose names are not in `owner/repo` form no longer print `invalid aqua tool` repeatedly. A name that no registry defines still fails with `package not found`. [#15048](https://github.com/jdx/mise/pull/15048) (@jdx, @trothwell)
- A version file that links to a sibling version file, such as `.nvmrc -> .node-version`, no longer prints a `not reading` warning. Links to other files are still not read and still warn. [#15058](https://github.com/jdx/mise/pull/15058) (@jdx, @owpac)
- Packslip versions held back by `minimum_release_age` or `--before` are now logged at debug level instead of printing one warning per version. [#15056](https://github.com/jdx/mise/pull/15056) (@jdx, @owpac)
- Gem wrapper scripts now quote `GEM_HOME` and the executable path, so gems work when the install directory contains spaces or shell metacharacters. [#15055](https://github.com/jdx/mise/pull/15055) (@jdx)
- Remote git sources (HTTPS and SSH) now reject a `ref` that is empty, is `HEAD`, or starts with `-`. This stops option injection into git, and these sources now follow the same rules as plain git repo sources. [#14832](https://github.com/jdx/mise/pull/14832) (@Huge)
