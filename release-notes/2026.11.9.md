# Task lock pools, tag-based task dependencies and Unix socket sandboxing

Task locks can now hold several slots and take templated names, task dependencies can be selected by tag, and sandboxed commands can block Unix socket connections. aqua tools shipped as a `.jar` now run directly. This release also fixes problems in `mise lock --bump`, `minimum_release_age`, shims on macOS, task caching, Homebrew casks and formulas, and dotfiles.

## Added

### Tasks

- **Lock pools.** A task `lock` can now be shared by several runs at once, so you can guard a limited resource such as CPU cores instead of making every heavy task wait in line. Set a lock's slot count once in `task.lock_pools`, then have each task take `count` slots. A task gets all of its slots or none. A task that doesn't fit waits and prints which tasks hold the pool. `MISE_TASK_LOCKS` lists the slots the task holds (for example `cpu,cpu:1,cpu:2`). A name with no `task.lock_pools` entry still has one slot, so existing `lock = "name"` tasks behave as before. Waiting tasks aren't queued, so a steady stream of small tasks can keep a large one waiting. [#15720](https://github.com/jdx/mise/pull/15720) (@jdx, @brodienguyen, @davdroman)

  ```toml
  # ~/.config/mise/config.toml
  [settings.task.lock_pools]
  cpu = "8"

  # mise.toml
  [tasks.lint]
  lock = "cpu"                                    # one slot

  [tasks.test]
  lock = [{ name = "cpu", count = 4 }, "test-db"] # four slots
  ```

- **Templates in lock names.** Lock names are now rendered as templates. This lets a project use its own lock, so unrelated projects that use the same lock name no longer wait on each other. `mise tasks info` shows the rendered name. A name that renders empty or contains a comma or control character is an error. [#15710](https://github.com/jdx/mise/pull/15710) (@jdx, @six5536)

  ```toml
  [tasks.w]
  lock = "package-lock.json-{{ config_root | hash(len=8) }}"
  ```

- **Select dependencies by tag.** `depends`, `depends_post` and `wait_for` accept `{ tag = ... }` with one tag or a list. They select every task that has any of those tags. Add `task` to the same entry to keep only the matching tasks that have the tag. A tag that matches no task is an error unless `optional = true`, and a task never depends on itself. The string form `"tag:lint"` isn't supported because `:` already separates task namespaces. [#15753](https://github.com/jdx/mise/pull/15753) (@jdx)

  ```toml
  [tasks.ci]
  depends = [{ tag = "lint" }, { tag = ["test", "slow"] }]
  ```

- **Unix socket sandboxing.** `mise exec` and `mise run` accept `--deny-unix` and `--allow-unix=<path>`, and tasks accept `deny_unix` and `allow_unix`. They block connections to Unix sockets such as an SSH agent or the container runtime socket, which `--deny-net` doesn't cover. `allow_unix` implies `deny_unix` and accepts a socket or a directory. These restrictions need Linux 7.1 or later. Older kernels and macOS exit with an error instead of running without the restriction, and Windows warns. `--deny-all` doesn't turn this on. [#15672](https://github.com/jdx/mise/pull/15672) (@jdx, @jonerrr)

  ```toml
  [tasks.agent]
  run = "omp"
  deny_unix = true
  allow_unix = ["/run/user/1000/allowed-service.sock"]
  ```

- `mise tasks ls --json` now includes each task's `cache`, `lock` and `skip_if` in the same format as `mise tasks info --json`. [#15675](https://github.com/jdx/mise/pull/15675) (@jdx)

### Tools

- **aqua `.jar` packages run directly.** On Unix, aqua packages shipped as a single jar, such as `Kotlin/ktfmt` and `checkstyle`, now get a launcher script that runs `java -jar`. You can call the tool by name. mise doesn't install Java for these tools, so add `java` to your tools. Windows isn't supported yet. [#15688](https://github.com/jdx/mise/pull/15688) (@jdx)
- New registry tools: `jadx` [#15685](https://github.com/jdx/mise/pull/15685) (@jdx) and `jscpd` [#15696](https://github.com/jdx/mise/pull/15696) (@jdx, @FalkWoldmann).

## Changed

- `[dotfiles]` block and line edits that also set a whole-file key such as `variants` or `enabled` now warn and are ignored. Before, mise misread them: the edit applied without its selector, or `mise dot apply` failed with "sources do not exist". [#15733](https://github.com/jdx/mise/pull/15733) (@jdx)
- `[dotfiles]` entries, `[dotfile_groups.*.entries]` and `[bootstrap.hooks]` now warn once about keys mise doesn't read, such as `env = "work"`, which previously did nothing without telling you. The entry still applies. To limit a whole-file entry to an environment, use `variants = [{ profile = "work" }]`. [#15735](https://github.com/jdx/mise/pull/15735) (@jdx, @Guria, @miroslavkrysl)

## Fixed

### Lockfiles and release age

- `mise lock --bump` no longer moves a tool to an older version when the remote version list is behind the lockfile. It keeps the locked version and prints a warning. This applies only when both versions are SemVer. [#15687](https://github.com/jdx/mise/pull/15687) (@jdx)
- `mise lock --bump` no longer writes the request text (for example `1`) as the locked version when `minimum_release_age` hides every matching release. It keeps the existing locked version. If no version is locked, the error names the hidden release and the cutoff. [#15689](https://github.com/jdx/mise/pull/15689) (@jdx)
- With `minimum_release_age`, `mise install` no longer installs an older release of a `latest` tool when a newer installed version is already newer than the cutoff, which `mise prune` would then remove. `mise install tool@latest` and `--force` work as before. [#15673](https://github.com/jdx/mise/pull/15673) (@jdx)
- zig lockfile entries now record `provenance = "minisign"`, so `mise lock --bump` no longer fails with a provenance downgrade error. [#15730](https://github.com/jdx/mise/pull/15730) (@jdx)
- When `mise lock` refuses a provenance or signer downgrade, the error now names the tool, version, platform and backend, and shows what the old and new entries record. [#15755](https://github.com/jdx/mise/pull/15755) (@jdx)
- npm tools installed with the embedded aube installer no longer apply aube's default 24-hour release age gate to dependencies when mise applies no cutoff. This covers `minimum_release_age = "0s"`, tools in `minimum_release_age_excludes` and exact-version installs. The gate could cause `trustPolicy=no-downgrade` failures. [#15697](https://github.com/jdx/mise/pull/15697) (@jdx)

### Shims, shell and self-update

- On macOS, a shim that installed a tool when no `mise` was on `PATH` could rewrite every shim as a symlink to itself, which broke all of them with "too many levels of symbolic links". Shims now keep pointing at mise. If mise can't find its own executable, it warns and leaves the shims unchanged. [#15758](https://github.com/jdx/mise/pull/15758) (@jdx, @redondos)
- zsh no longer prints `compdef` errors on every prompt when `_comps` is a plain array, which happens in shells rebuilt from a snapshot, such as Claude Code. [#15692](https://github.com/jdx/mise/pull/15692) (@jdx)
- On Windows, `mise self-update` now downloads the release archive once instead of twice. [#15686](https://github.com/jdx/mise/pull/15686) (@jdx)
- `mise --version` no longer calls the official deb, rpm and npm packages a third-party build. [#15690](https://github.com/jdx/mise/pull/15690) (@jdx)
- When a deferred cleanup of old tool versions runs during an unrelated command, tracked configs that fail to load now produce one summary warning instead of one warning per file. Run `mise prune --dry-run` for the details. [#15698](https://github.com/jdx/mise/pull/15698) (@jdx, @kapitoshka438)

### Tasks

- A cached task no longer stores a pass when one of its sources changed or a new file matched its sources during the run. It warns `changed while the task ran; not caching` instead, so a later run can't restore a result from different content. [#15719](https://github.com/jdx/mise/pull/15719) (@jdx)
- `mise cache clear --task '<pattern>'` now reads the cache once instead of twice for each matched task. It no longer gets slower as the cache grows. [#15718](https://github.com/jdx/mise/pull/15718) (@jdx)

### Bootstrap and Homebrew

- `mise bootstrap --update` now pulls the global config checkout even when its current commit has invalid TOML, so a machine can get the fix from upstream. [#15731](https://github.com/jdx/mise/pull/15731) (@jdx, @Guria)
- On Linux, casks whose artifacts mise can't handle, such as AppImage casks, are now shown as skipped. Before, they broke `mise bootstrap packages status` and made `apply` fail. [#15732](https://github.com/jdx/mise/pull/15732) (@jdx)
- These Homebrew casks and formulas now install:
  - Tap casks that use `version.csv.second` and similar helpers, when `homebrew_metadata = true`. [#15708](https://github.com/jdx/mise/pull/15708) (@jdx)
  - Source formulas that use `with_env`, such as `can1357/tap/omp`. [#15737](https://github.com/jdx/mise/pull/15737) (@jdx)
  - Casks that download a binary from a URL with no filename, such as `muse-code`. [#15738](https://github.com/jdx/mise/pull/15738) (@jdx)
  - Casks whose binary is a nested app bundle, such as `surge`. [#15739](https://github.com/jdx/mise/pull/15739) (@jdx)
  - Tap casks that declare `installer script:`. Cask artifact errors now also name the cask. [#15743](https://github.com/jdx/mise/pull/15743) (@jdx)

### Backends and other fixes

- vfox plugins can call `http.get` and other async functions inside `pcall`. This fixes installs of `vfox:version-fox/vfox-python` 0.6.4. [#15741](https://github.com/jdx/mise/pull/15741) (@jdx)
- Erlang now installs the precompiled build on GitHub's `ubuntu-slim` runner. When `ImageOS=Linux`, mise reads `/etc/os-release` instead of rejecting the OS. [#15691](https://github.com/jdx/mise/pull/15691) (@jdx)
- `mise search` now shows a registry entry's `url` instead of guessing a GitHub link. For example, `oc` now links to `openshift/oc`. [#15709](https://github.com/jdx/mise/pull/15709) (@jdx)
- `hook-env` does less work on each prompt and directory change. [#15734](https://github.com/jdx/mise/pull/15734) (@jdx, @FalkWoldmann)

## Documentation

- The docs now explain that `MISE_GLOBAL_CONFIG_FILE` and `MISE_SYSTEM_CONFIG_FILE` load only the named file, without its `MISE_ENV` variants or `.local` files. To use a variant, point the variable at that file. [#15716](https://github.com/jdx/mise/pull/15716) (@jdx, @simonepri)
