# mise showreel: art spec

This is the production look that replaces the grey-box. Builders follow it. The numbers live in `kit/style.ts` and are imported from there, never retyped. The storyboard (`STORYBOARD.md`) says what happens and when; this file says what it looks like and how it moves.

The art pass checked these tokens on 15 still style frames drawn from the real captures with the engine's own fx, type and terminal code (scratch, not in the repo; for this build they are in the session scratchpad under `build/art/out/`, with `styleframes-sheet.png` holding all of them). Where this spec and a style frame disagree, the spec wins.

## 1. Identity

The reel is hk's and Mr Boxington's sibling: the same engine, stage, caption motion, terminal grid and honesty. It is mise's through five things neither of them has.

|         | Shared with hk and mbx                                                         | Only mise                                                                                                                                         |
| ------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stage   | Dark stage one step below the page, vignette, 24 fps grain, lit screens spared | Plum-black `#171417` under a warm **pass lamp** from above; paper motes rise round the chef                                                       |
| Colour  | One accent family, paper `#f4eee3` captions                                    | **Four pillar colours**, each meaning one thing only, taught by the station card                                                                  |
| Type    | Space Grotesk captions that rise word by word, mono on a fixed grid            | **Cormorant Garamond italic** for tickets and the name: the first serif in the family                                                             |
| Devices | Terminal windows, code cards, badges, sparks on arcs, kinetic big type         | The **station card** (one `mise.toml` that folds, lights and seats lines) and the **ticket rail** (paper order tickets that print, tear and lift) |
| Mascot  | Logo draw-on (hk), character box (mbx)                                         | The **chef**: block chef in the real help screen resolving into the vector chef; the card's three headers become the toque's three lobes          |

## 5. Layout

The grid (`LAYOUT`, `PANES`): a left column x 160–1100 for the terminal, a 40 px gutter x 1100–1140 where threads run, and a right column x 1140–1760 for the card and whatever takes its place. Actors stand in y 120–690, footnotes sit on baseline 738 (about 20 px clear of the actor band and of a two-line caption's first cap height), captions start at 740. The open has no captions, so its help pane may be fitted to its eight rows and centred in the frame (`fitPane`, `placePane`); the mosaic's target, the chef's place, does not move.

**Size panes and cards to their content.** A screen that shows a few rows sits in a pane as tall as it needs, not in 570 px of empty window: `fitPane(p, rows)` (kit/term.ts) cuts a preset down to hold its rows (at least `FIT_MIN`, 6), `fittedPane(c, ct, p)` (kit/rest.ts) and `shot`'s `fit` grow one from a take as its output needs rows (the bottom edge moves over 1/4 beat, move; never shrinking on its own), and a card's `fit` follows its own rows as tables fold and seat (`cardFit`). The top-left corner stays on the grid; `centreIn` / `placePane` move a fitted pane where a scene wants it centred. A pane or card that rests on a bar line fits the same way on both sides (`PaneRest.fit`).

### Named easings (`EASE`)

| Name     | Curve                          | Use                                                                 |
| -------- | ------------------------------ | ------------------------------------------------------------------- |
| `arrive` | cubic-bezier(0.16, 1, 0.3, 1)  | Entrances, settles, draw-ons, header lighting                       |
| `leave`  | cubic-bezier(0.7, 0, 0.84, 0)  | Exits, lift-offs, unlighting                                        |
| `move`   | cubic-bezier(0.83, 0, 0.17, 1) | Rest to rest: rects, panes shrinking, zooms, folds, lanes settling  |
| `glide`  | sine in-out                    | Dims, the lamp, push-ins, colour drains                             |
| `settle` | outCubic                       | Small stops; each printer step                                      |

### Rules

| Rule              | Detail                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grid              | Every move starts and ends on the 1/16-beat grid of its section, or on a take's own time (keys, printed rows), or on a measured onset (end card).                                                                                                                                                                                                                                                                |
| Rest on bar lines | Anything a bar line keeps (`kit/rest.ts`) is exactly at rest from 1/120 s before the line to 1/120 s after it. No pulse, glow, overshoot or ease crosses a bar line; ambient motion (grain, motes, cursor, spinner) runs on global time, so both sides agree.                                                                                                                                                    |
| Rests             | A bar line never rests on an empty, untitled window: a terminal it keeps shows the outgoing take's last screen (`HOLDS`) or the incoming take's opening prompt (`OPENS`), and the other side dissolves its own screen into that one (`restScreen`). The section before a ticket never clears its own stage: the ticket takes it down. A card or pane that fits its content (§5) fits the same way on both sides. |
| Anticipation      | Only for weighty moves off a rest: the ticket's lift, block cells, header bands in the morph, the ledger into its chip, the whip's wind-up. 1/8 beat (the whip: 1 beat), 4–8 px or 2–3 % opposite the move. Never on text arriving, never on captions.                                                                                                                                                           |
| Overshoot         | 12 % (`snap`) for small things landing; 6 % (`drop`) for heavy things; none for windows, cards, panels, captions, badges or anything moving between two rests.                                                                                                                                                                                                                                                   |
| Enter / exit      | Windows and cards rise 24 in and fall 16 out; file cards come from their source row or 60 px from the right; diagrams draw on; small marks pop (scale 0.9 → 1, or 0 → 1 for dots and nodes only). Nothing enters by scaling up from 0 except glyph-sized marks.                                                                                                                                                  |
| Captions          | A caption starts to write in half a beat after its subject is on screen and still, and nothing else starts a move until half a beat after its last word lands (STORYBOARD.md "Pacing").                                                                                                                                                                                                                          |
| Stagger           | 1/16 beat per item, capped so a cascade takes at most 1/2 beat.                                                                                                                                                                                                                                                                                                                                                  |
| Honesty           | Motion never edits captured text: copies lift, originals stay; crops are the pane's fade or a viewport crop; install rows move only under the time-lapse badge.                                                                                                                                                                                                                                                  |

## 14. Do and don't

| Do                                                                              | Don't                                                                                                    |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Import every number from `kit/style.ts`                                         | Retype a hex, size or duration in a scene                                                                |
| Use a pillar colour only where §2 lists it                                      | Put a pillar colour on a badge, thread, stamp, tick, keycap, chrome, prompt or (except machine) the whip |
| Keep captured text verbatim, cropped only by the pane's fade or a viewport crop | Re-wrap, abbreviate or recolour captured text (annotations are Space Grotesk pills, never mono)          |
| Keep story-critical type at 40 px or more and mono at 26 px or more             | Ask a viewer to read 20–24 px (checksums, dimmed prose and micro badges are texture)                     |
| Route threads through gutters and margins, ending in anchor dots                | Cross glyphs with a thread or a join                                                                     |
| Give raised objects `raised` + `contact` shadows and a top-edge highlight       | Put diagrams in boxes, or shadows under flat diagrams                                                    |
| Draw masked effects (glint, lobe tint) on the object's own offscreen layer      | Composite `source-atop` onto the frame: it paints the background too                                     |
| Draw block glyphs as full-cell vectors with 0.5 px overscan                     | Leave seams between block rows                                                                           |
| Land every held layer at rest before its bar line                               | Let a pulse, ease or overshoot cross a bar line                                                          |
| Mark a pass with a paper tick and the bell                                      | Use sage for "passed", or red outside a pane                                                             |
| Keep the chef's eyes still; motes as specks                                     | Animate the eyes, or add steam clouds, knives, pans or any kitchen prop but tickets and the chef         |
| Show counts, versions and times only as captured text or caption tokens         | Draw a count, a timing or a rate as art (no "1009", no timers, no progress bars)                         |
| Keep the whip the only smear and `prod` the only shake                          | Use motion blur, `ctx.filter` blur, or camera shake anywhere else                                        |
| Remove the grey-box's dashed boxes, "(art later)" tags and stage-plan lines     | Ship a placeholder, or a label that describes the art                                                    |
