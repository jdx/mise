**On the hang before anything shows.** Yes, that's the resolver. Here's the sequence for `mise install`:

1. `Toolset::resolve` fetches every tool's remote version list — in parallel, but the step ends when the *slowest* one does. `node@22` goes to `mise-versions.jdx.dev` and falls back to nodejs.org/dist/index.json; the GitHub tools hit `api.github.com`. Each is one DNS lookup against `192.168.0.1` with no fallback; a stuck lookup waits the full `fetch_remote_versions_timeout` (default 20s) before retrying.
2. Only *after* that does `install_missing_versions` know which versions exist and create the progress session. Nothing in either renderer runs before this point — no header, no rows.

On a healthy network step 1 is well under a second (my timed run: first row at 0.00s; the mise-versions cache answers instantly), so this is mostly invisible outside of today's DNS. In CI logs the gap shows as a timestamp jump before `mise by @jdx – installing…`.

**Is it easily fixable?** Partially and cheaply, fully with moderate work:

- *Cheap (an hour):* start the session before resolution in `mise install` (and `upgrade`), since the requested tools are known up front. Header appears immediately with `mise by @jdx  ░░░░  0/7 · 2.1s` and rows say `resolving` from t=0, so the wait is visible and attributable. Rows are keyed by short name until the version comes back, then relabelled — `set_prefix` already exists for that. Tools that turn out to be already installed close as `already installed` (that outcome exists too). Scope: cli/install.rs + `toolset_install.rs` accept an existing session instead of always creating one; other callers (`mise x`, `mise use`) keep the current behavior.
- *Not cheap:* making `resolve` itself report per-tool progress ("waiting on nodejs.org") — that's threading a reporter through every backend's `list_remote_versions`. Not worth it for a step that's normally sub-second.

My recommendation: the cheap version, but as a follow-up PR — [#12906](https://github.com/jdx/mise/pull/12906) is already large and in its fourth review round. I can start it now on a branch stacked on this one if you'd rather have it in hand.
